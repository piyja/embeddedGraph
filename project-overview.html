Vision
Why this project exists

Edge devices now run small LLMs (Phi-3, Gemma 2B, Qwen 0.5B) that produce probabilistic outputs. Embedded systems need a deterministic orchestrator to manage these non-deterministic components safely. LangGraph solved this for the cloud. This project solves it for the edge — and the graph + HSM core is general-purpose: any smart application that needs structured routing with a safety shell can use it, AI or not.

C++20 Runtime
Header-only graph engine, HSM, and inference abstraction. Zero dependencies in stub mode. Builds with any C++20 compiler. Designed for AUTOSAR Adaptive Platform targets. Template-based — state is always a plain user struct.
Static Allocation Mode
Compile with -DEMBG_STATIC_ALLOC for zero heap allocation: fixed-capacity StaticString, StaticMap, StaticVector, and SBO Function. Same API, same application code. For MCU / RTOS / safety-critical targets where dynamic allocation is forbidden.
Embedded Primitives
Primitives LangGraph lacks: confidence-gated transitions, hard timeout nodes, degraded-mode graph selection, budget-aware scheduling. The deterministic shell retains veto power over the stochastic core.

Pattern
The two-layer architecture

HSM manages the deterministic behavioral contract. Graph runs the agentic inference loop inside an HSM state. This separation is what makes AI safe in embedded: the HSM is formally verifiable, the graph is not.

Layer 1 — Deterministic
HSM (Hierarchical State Machine)
Manages coarse system modes: OPERATING, DEGRADED, SAFE_HALT. Entry/exit actions guaranteed. Event propagation up the hierarchy. LCA-based UML 2.0 transitions. This is the safety contract.
OPERATING → AI available, full graph runs
DEGRADED → AI unavailable, rule-based only
SAFE_HALT → ASIL-D safe state, all stopped
Layer 2 — Stochastic
Graph (Execution Engine)
Runs inside an HSM state. Manages the agentic loop: reason, tool-call, observe, repeat. Confidence-gated transitions. Hard timeouts. The LLM decides edges; the graph enforces constraints.
reason → LLM decides next action
tool_execute → run selected tool
[conf gate] → veto low-confidence finishes

API
Core concepts

Four classes form the C++ framework. State type S is always a plain user-defined struct.

embg::Graph<S>
Execution engine. Templated on state struct. Nodes mutate state; routers read it. Cycles are first-class.
.add_node(name, fn)
.add_edge(from, to)
.add_conditional_edge(from, router)
.set_entry(name)
.on_step(fn) // streaming
.set_interrupt(name, fn)
.run(state, max_steps)
embg::hsm::HSM<S>
Hierarchical state machine. LCA-based UML 2.0 transitions. Parent states handle events children don't.
.add_state({name, parent, on_entry, on_exit, ...})
.set_initial(name)
.on_transition(fn)
.init(state)
.dispatch(event, state)
.current() → string_view

Embedded
Primitives LangGraph lacks

Edge/embedded systems need guard conditions that are probabilities, not booleans. Deadlines that are hard, not soft. Graphs that degrade gracefully.

Confidence-gated router
Guard condition is a probability threshold, not a boolean. If model confidence < 0.85, route to fallback instead of acting on the LLM decision.
auto router = embg::embedded::confidence_router<State>( 0.85, // threshold "act", // above → trust model "fallback" // below → rule-based );
Hard timeout wrapper
Every LLM node has a deterministic deadline. If inference exceeds the budget, the fallback fires automatically. No hung threads in safety-critical paths.
auto safe_node = embg::embedded::with_timeout<State>( inference_fn, std::chrono::milliseconds(50), fallback_fn );
Degraded mode runner
Capability-layered execution. Select which graph to run based on power, thermal, connectivity. Full AI → rule-based → minimal safe state.
embg::embedded::DegradedModeRunner<State> runner; runner .add_level(Full, full_graph) .add_level(Degraded, rule_graph) .add_level(MinimalSafe, halt_graph);
ConfidenceState concept
C++20 concept constraining which state types can use confidence routing. Any struct with a last_confidence field qualifies. Compile-time safety.
template<typename S> concept ConfidenceState = GraphState<S> && requires(const S s) { { s.last_confidence } → std::convertible_to<double>; };

Safety
Automotive safety context

AI components are non-deterministic. Safety standards require deterministic verification. The solution: decompose the safety requirement across an AI component and a safety monitor.

ASIL Decomposition
AI Component (ASIL-B) handles nominal case with high performance. Safety Monitor (ASIL-C, deterministic) validates AI output and enforces hard invariants. Combined: ASIL-B × ASIL-C = ASIL-D equivalent. The monitor can veto any AI decision.
Degraded Mode Graph
Full graph — LLM available, battery > 30%, thermal OK
Simplified graph — battery low OR thermal throttle → rule-based heuristics only
Minimal safe state — critical fault → halt, alert, wait for recovery
Standards Stack
ISO 26262 — Functional safety, ASIL A→D
ISO 21448 (SOTIF) — AI/ML sensor uncertainty and non-determinism
MISRA C++:2023 — Coding guidelines for safety-critical C++
AUTOSAR Adaptive — High-compute platform (POSIX, C++17) for AI-capable ECUs
All-C++ Safety Story
The current path is all-C++ — simplicity and independence are the safety story, not language choice. Static allocation mode eliminates heap. The FFI seam remains open should a Rust core ever be revisited via extern "C" bindings.
The orchestrator is the contract between the deterministic world and the stochastic one. Embedded systems will need what avionics already have — formal behavioral specifications — but now those specifications must safely contain probabilistic inference engines.

Roadmap
Development phases

From C++ prototype to dual-language embedded orchestrator.

Phase 1
Functional core on Linux/POSIX done
Header-only graph engine, HSM, inference abstraction, embedded primitives. 7 runnable examples. StubEngine for dev, LlamaCppEngine skeleton for production.
Graph<S> HSM<S> InferenceEngine Embedded
Phase 2
Replace std::async with RTOS task primitives
with_timeout currently uses std::async (thread + heap). In static mode the async path is compiled out. Full RTOS-task-based timeout enforcement for bare-metal targets is next.
with_timeout RTOS
Phase 3
Replace heap allocation with static pools / std::array done
Compile with -DEMBG_STATIC_ALLOC to get fixed-capacity storage: StaticString, StaticMap, StaticVector, SBO Function. No dynamic allocation. Application code unchanged in both modes. HSM transition scratch buffers moved to members — zero per-transition heap.
StaticString StaticMap Function (SBO) EMBG_STATIC_ALLOC
Phase 4
Replace exceptions with error codes / std::expected
Current code throws std::runtime_error on logic errors (unknown node, max_steps exceeded). Static mode still throws. Phase 4 adds a no-exception mode for freestishing environments.
no-exceptions std::expected
Phase 5
MISRA C++:2023 compliance audit
Coding guidelines for safety-critical C++. Static analysis, rule compliance, certification artifacts for ISO 26262 / SOTIF.

Phase 6
Bare-metal port (Cortex-M / RISC-V)
Port to freestanding environments. No OS, no heap, no exceptions. RTOS task primitives for timeout. Static allocation mode required.

Getting started

GCC 13+ or Clang 16+. No dependencies beyond the C++20 standard library.

# Build all C++ examples (default heap mode)
cd cpp && make

# Build in static-allocation mode (no heap)
make STATIC=1

# Build both modes, run all examples, diff output — must match
make check

# Run the LLM brain agent
./build/07_llm_brain_agent

# Clean
make clean
In classical systems, you decide the edges. Transition conditions are deterministic code you wrote. In LLM systems, the LLM decides the edges — based on natural language understanding of unstructured output. The graph structure is partially runtime-dynamic. That is genuinely novel and requires new infrastructure.
