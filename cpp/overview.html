API
Core concepts

Three classes form the full framework. State type S is always a plain user-defined struct.

embg::Graph<S>
Execution engine. Templated on your state struct. Nodes mutate state; routers read it. Cycles are first-class.
.add_node(name, fn)
.add_edge(from, to)
.add_conditional_edge(from, router)
.set_entry(name)
.on_step(fn) // streaming
.set_interrupt(name, fn)
.run(state, max_steps)
embg::hsm::HSM<S>
Hierarchical state machine. LCA-based UML 2.0 transitions. Parent states handle events children don't.
.add_state({name, parent, on_entry, on_exit, handlers, initial})
.set_initial(name)
.on_transition(fn)
.init(state)
.dispatch(event, state)
.current() → string_view
INTERNAL / UNHANDLED sentinels
embg::inference
Engine abstraction. Swap StubEngine for LlamaCppEngine without touching node logic.
InferenceEngine::generate(req) → Response
StubEngine.add_response(kw, text, conf)
LlamaCppEngine(model_path) // #ifdef guard
make_node<S>(engine, build_prompt, apply)
Response: {text, confidence, timed_out}
Request: {system_prompt, user_prompt, max_tokens}
Examples
Seven runnable examples

Each builds on the previous. Run with make && ./build/07_llm_brain_agent

01
simple_chain
Linear pipeline with a conditional branch. Two inputs route to different response nodes based on keyword classification. Baseline LangChain equivalent.
Graph<S> conditional_edge on_step
preprocess → classify → [router] ├─▶ respond_technical → END └─▶ respond_general → END
02
agent_loop
Cyclic ReAct agent. The agent picks a tool, executes it, then loops back to decide the next step. Demonstrates cycles — impossible in a DAG-only framework.
Graph<S> cycles tool dispatch
agent ←─────────────────┐ │ │ └─[router]─▶ tool_execute ▶ END (when done)
03
embedded_sensor
Temperature sensor with confidence-gated routing. Model inference runs on each cycle. Below-threshold confidence triggers deterministic rule-based fallback.
confidence_router DegradedModeRunner ConfidenceState
read_sensor → inference → [conf ≥ 0.85?] ├─▶ act_on_inference → log └─▶ rule_based → log
04
automotive_diagnostic
Full automotive agent: loops calling CAN bus, DTC, live PIDs, actuator tests. Confidence grows with evidence. Below 0.85 sends the agent back for more data.
agent loop confidence gate degraded mode
agent ←──────────────────────────┐ │ │ ├─▶ tool_execute → inference │ │ [conf ≥ 0.85] ─▶ report │ │ [conf < 0.85] ────────────┘ └─▶ report (tools exhausted)
05
hsm_ecu_states
HSM manages coarse system states. Graph runs inside HSM states. critical_fault handled at OPERATING parent level — correct exit/entry propagation through the hierarchy.
HSM<S> hierarchy entry/exit Graph inside HSM
OPERATING (parent) ├── NORMAL ← runs Graph on entry └── ALERT ← runs Graph on entry DEGRADED ← rule-based only SAFE_HALT ← ASIL-D safe state
06
llm_diagnostic
InferenceEngine node plugged into the diagnostic agent. StubEngine by default. One-line swap to LlamaCppEngine for real on-device inference with no graph changes.
InferenceEngine make_node() StubEngine confidence gate
agent → tool_execute → inference_node [embg::inference::make_node()] ↓ [conf_router] → report | agent
07
llm_brain_agent — LLM as the orchestration brain
The model decides which tool to call next and when it has gathered enough evidence — not the programmer. The reason node calls the inference engine, parses a structured decision (ACTION / TOOL / REASONING), and the graph routes accordingly. A confidence gate overrides the model's "finish" decision if confidence is below threshold — the deterministic shell retains veto power.
LLM orchestrates ReAct loop confidence gate structured output make_node()
reason ←───────────────────────────┐ │ [LLM decides: ACTION + TOOL] │ ├─▶ tool_execute ─────────────────┘ (loop: model picks tools) └─▶ [confidence gate] conf ≥ 0.85 ─▶ report_fault ─▶ END conf < 0.85 ─▶ reason again (override model's finish)
Integration
Wiring llama.cpp

Three steps to replace StubEngine with a real on-device model.

01
Build llama.cpp
Clone and build the shared library. CMake handles dependencies.
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
cmake -B build -DBUILD_SHARED_LIBS=ON
cmake --build build --config Release -j$(nproc)
02
Download a GGUF model
Choose based on your target hardware. Q4 quantisation recommended for embedded.
ModelSizeRAMTargetNotes
Qwen2.5 0.5B Q8 ~500 MB ~700 MB fast CPU Smallest. Cortex-A series, automotive SoC
Phi-3 Mini 3.8B Q4 ~2.2 GB ~2.8 GB good CPU Strong reasoning. NVIDIA Jetson / x86 embedded
Gemma 2 2B Q4 ~1.5 GB ~2 GB good CPU Instruction following. Raspberry Pi 5 / AM6x
TinyLlama 1.1B Q4 ~670 MB ~900 MB fast CPU Minimal footprint. Lower reasoning quality
03
Swap the engine in your example
One-line change in main(). Everything else — graph topology, confidence routing, degraded mode — stays identical.
// Before (stub, no model needed):
embg::inference::StubEngine engine;

// After (real llama.cpp model):
#ifdef LG_WITH_LLAMACPP
embg::inference::LlamaCppEngine engine("/path/to/model.gguf");
#endif

// Compile with:
// g++ -std=c++20 -DLG_WITH_LLAMACPP \
//     -I include -I /path/to/llama.cpp/include \
//     examples/07_llm_brain_agent.cpp \
//     -L /path/to/llama.cpp/build -lllama -lpthread \
//     -o build/07_llm_brain_agent
Static Mode
Resource-constrained mode (no heap)

Compile with -DEMBG_STATIC_ALLOC to replace all std::* containers with fixed-capacity preallocated storage. The application code is identical in both modes — the build flag selects the storage strategy.

StaticString<N>
Null-terminated fixed buffer. Implicit const char* ctor so add_node("preprocess", ...) compiles unchanged.
StaticMap<K,V,Cap>
Flat array of pairs, O(N) lookup. N is tiny (≤16). No heap. insert_or_assign, find.
Function<Sig,Bytes>
SBO callable. Stores lambda inline up to N bytes. static_assert with clear message if capture too large.

Tune capacities in config.hpp (StaticConfig):

ParameterDefaultControls
MaxNodes16Max nodes per graph
MaxEdges16Max edges per graph
MaxHsmStates16Max states in HSM
MaxHsmDepth8Max nesting depth (scratch buffer)
MaxStrLen32Node/state/event name length
MaxPromptLen512Inference prompt/response length
FnInlineBytes64SBO size for router/step lambdas
NodeFnInlineBytes256SBO size for node lambdas (inference nodes larger)
Build
Getting started

GCC 13+ or Clang 16+. No dependencies beyond the C++20 standard library.

# Build all examples (default heap mode)
cd cpp
make

# Build in static-allocation mode (no heap)
make STATIC=1

# Build both modes, run all examples, diff output — must match
make check

# Run a specific example
./build/07_llm_brain_agent

# Clean
make clean
